Slide 2

10 Interview Questions (Previous Lessons)

  1. What is the practical difference between HashMap and LinkedHashMap, and when would you choose each?

    Use HashMap when order is irrelevant and fast average lookup is the goal. Use LinkedHashMap when insertion/access order must be preserved (for example predictable iteration or simple LRU behavior).

  2. Explain checked vs unchecked exceptions. In a service layer, where should each typically be handled?

    Checked exceptions model recoverable integration failures and are usually translated at boundaries. Unchecked exceptions model programming/domain violations and are usually handled by centralized global exception handling.

  3. Why are equals() and hashCode() critical for HashSet/HashMap? What bugs appear if the contract is broken?

    Hash collections use hashCode() for bucket selection and equals() for equality confirmation. Broken contracts cause missing keys, duplicate set items, and inconsistent remove/find behavior.

  4. What is the difference between Comparable and Comparator? Give one real sorting scenario for each.

    Comparable defines natural order in the class itself (e.g., user by id). Comparator defines external or context-specific order (e.g., same users by lastLogin desc in admin dashboard).

  5. Compare ArrayList and LinkedList in terms of get, append, and middle remove complexity.

    ArrayList has O(1) random access and amortized O(1) append but costly middle remove due to shifts. LinkedList has O(n) access; insert/remove is cheap after traversal, but traversal cost often dominates.

  6. When do you prefer an interface over an abstract class in Java API design?

    Prefer interface for capability contracts and multiple independent implementations. Prefer abstract class when you need shared state, protected helpers, and partial base behavior across subclasses.

  7. Explain wildcard usage: <? extends T> vs <? super T> with a producer/consumer example.

    Use ? extends T when reading from a producer collection, and ? super T when writing to a consumer collection. PECS rule: Producer Extends, Consumer Super.

  8. What is the difference between method overloading, method overriding, and static method hiding?

    Overloading changes signature in same class (compile-time resolution). Overriding changes inherited behavior polymorphically (runtime dispatch). Static hiding shadows parent static method based on reference type, not object type.

  9. Why does immutability reduce concurrency bugs? Name two immutable structures commonly used in Java.

    Immutable objects remove shared mutable state, reducing race conditions and synchronization needs. Common examples: String and immutable DTO/record types (or List.of(...) snapshots).

  10. What makes a functional interface valid, and when is a method reference better than a lambda?

    A functional interface has exactly one abstract method (default/static methods allowed). Method reference is preferable when it expresses identical behavior with better readability, e.g., String::trim.

Slide 3

Streams from Arrays, Empty, Generators

  • Arrays.stream(array) is the cleanest way to process arrays with stream operations.
  • Arrays.stream(array, from, to) is useful for slicing windows (for example, top 100 records).
  • Stream.empty() is perfect for safe defaults in APIs instead of null.
  • Stream.generate(...) and Stream.iterate(...) create infinite streams; always guard with limit(). 
String[] words = {"Java", "Stream", "API"};
Stream<String> streamOfWords = Arrays.stream(words);

Stream<String> emptyStream = Stream.empty();

Stream.generate(Math::random)
      .limit(5)
      .forEach(System.out::println);

Stream.iterate(1, n -> n + 1)
      .limit(5)
      .forEach(System.out::println);
Slide 4

Streams Have No Storage

  • Collections are in-memory containers; all elements exist there.
  • Streams are computation views over a source, evaluated when needed.
  • Intermediate operations (for example filter, map, sorted) return another stream and stay lazy.
  • Terminal operations (for example collect, forEach, count, reduce) trigger actual execution and produce a final result.
  • This design reduces unnecessary work and can improve performance on large datasets.
List<String> result = departments.stream()
    .filter(d -> d.startsWith("S"))   // intermediate
    .map(String::toUpperCase)         // intermediate
    .collect(Collectors.toList());    // terminal (executes pipeline)

Key takeaway: Stream pipelines are execution plans, not data structures.

Slide 5

Stream Pipeline: The Standard Execution Model

  • Stage 1 - Source: list, set, array, generator, file lines, etc.
  • Stage 2 - Intermediate operations: filter, map, sorted, distinct.
  • Stage 3 - Terminal operation: collect, reduce, count, findFirst.
  • Only one terminal operation per pipeline run.

Key takeaway: This model maps directly to business flows such as “filter valid orders, transform DTOs, collect response”.

Slide 7

map() Characteristics

  • map(Function) is intermediate and lazy, so it does nothing until terminal execution.
  • It returns a new stream, preserving immutability of the source collection.
  • Pipeline readability improves when each transformation has one clear purpose.

Key takeaway: Small, focused map operations are easier to debug and test than one large transformation block.

Slide 8

Streams flatMap() Method (Intermediate Operation)

  • Use flatMap() for one-to-many mappings (one input, many outputs).
  • map() creates nested structures; flatMap() flattens to one continuous stream.
  • Common scenarios: users to roles, orders to line items, departments to employees.

Input Words

Arrays.stream(words) .flatMap(word -> Arrays.stream(word.split(""))) .forEach(System.out::println)

flatMap() removes one nesting level and gives one continuous stream.

String[] words = {"Java", "Stream"};

Stream<String> letters = Arrays.stream(words)
    .flatMap(word -> Arrays.stream(word.split("")));

letters.forEach(System.out::println);
Slide 9

flatMap() with Person and Phone Numbers

  • map(Person::getPhoneNumbers) returns nested output (List<List<String>>).
  • flatMap(...) returns a single list of all numbers (List<String>).
  • Practical example: build one contact list for SMS notifications across all customers.
List<List<String>> mapResult = persons.stream()
    .map(Person::getPhoneNumbers)
    .collect(Collectors.toList());

List<String> flatMapResult = persons.stream()
    .flatMap(person -> person.getPhoneNumbers().stream())
    .collect(Collectors.toList());

Slide 11

Streams limit() Method (Intermediate Operation)

  • limit(n) restricts output to the first n elements.
  • It is mandatory when working with infinite streams.
  • In APIs, limit() is often used for previews, dashboards, and pagination windows.
  • On unordered sources, the “first n” concept depends on source behavior.
Stream.generate(() -> new Random().nextInt(100))
      .limit(10)
      .forEach(System.out::println);
Slide 12

Streams skip() Method (Intermediate Operation)

  • skip(n) discards the first n items and continues with the rest.
  • If stream size is smaller than n, the result is empty.
  • skip + limit is a clean foundation for page-based slicing.
Stream.iterate(1, n -> n + 1)
      .skip(5)
      .limit(5)
      .forEach(System.out::println); // 6, 7, 8, 9, 10
Slide 13

Streams Are Traversable Only Once

  • Streams are one-shot: after terminal execution, the stream is closed.
  • Reusing the same stream instance triggers IllegalStateException.
  • If you need another pass, rebuild the stream from the original source.
Stream<String> depStream = departmentList.stream();
depStream.forEach(System.out::println);
depStream.forEach(System.out::println); // IllegalStateException
Slide 14

Streams reduce() Method (Terminal Operation) - Concept

  • reduce folds many values into one final result.
  • It uses an identity (seed) and an accumulator function.
  • If stream is empty, identity becomes the result.
  • Great for totals, score aggregation, merging summaries, and composite object creation.
  • Numeric stream types expose optimized methods like sum(), average(), and max().

Key takeaway: Think of reduce as controlled accumulation with explicit business rules.

  • Second example: sum all person incomes for a reporting metric.
  • Same pattern scales to discounts, taxes, risk scores, and KPI totals.

Slide 18

Streams collectingAndThen() Method (Terminal Operation)

  • Run one collector first, then transform that collector output in a finishing step.
  • Pattern: collectingAndThen(downstreamCollector, finisher).
  • Useful when you want a polished final value (for example Optional to plain String).
String maxPriceProduct = productList.stream()
    .collect(Collectors.collectingAndThen(
        Collectors.maxBy(Comparator.comparing(Product::getPrice)),
        optionalProduct -> optionalProduct.map(Product::getName).orElse("None")
    ));

System.out.println("The product with max price tag is: " + maxPriceProduct);
Slide 19

Streams groupingBy() Method (Terminal Operation)

  • Groups elements by a classification key and returns a Map<K, List<T>>.
  • Equivalent mindset to SQL GROUP BY.
  • Ideal for reporting dashboards (for example products grouped by price band/category).
Map<Integer, List<Product>> groupByPriceMap = productList.stream()
    .collect(Collectors.groupingBy(Product::getPrice));

System.out.println(groupByPriceMap);
Slide 20

Streams partitioningBy() Method (Terminal Operation)

  • Splits data into exactly two buckets using a predicate: true and false.
  • Returns Map<Boolean, List<T>> so both sides are available at once.
  • Great for “eligible vs not eligible”, “premium vs regular”, “pass vs fail” use cases.
Map<Boolean, List<Product>> products = productList.stream()
    .collect(Collectors.partitioningBy(product -> product.getPrice() > 1000));

System.out.println(products);
Slide 21

Finding and Matching Methods in Streams

  • Core operations: allMatch, anyMatch, noneMatch, findAny, findFirst.
  • All are terminal operations and can stop early (short-circuit behavior).
  • This makes them efficient for validation gates and quick checks.
  • findAny/findFirst return Optional<T> to model “might be absent”.
Slide 22

Find and Match Example - Part 1

  • allMatch checks whether every item satisfies inventory availability.
  • anyMatch checks whether at least one item is on sale.
  • These checks are common in checkout preconditions and campaign logic.
boolean allInStock = items.stream().allMatch(Item::isInStock);
System.out.println(allInStock);

boolean anyOnSale = items.stream().anyMatch(Item::isOnSale);
System.out.println(anyOnSale);

Key takeaway: Use match methods when you need a direct boolean decision from a collection.

Slide 23

Find and Match Example - Part 2

  • noneMatch is ideal for policy guards (“no dangerous item”, “no invalid state”).
  • findAny is fast in parallel contexts; findFirst preserves encounter order.
  • Always handle Optional explicitly instead of calling get() blindly.
boolean anyOutOfStock = items.stream().anyMatch(item -> !item.isInStock());
System.out.println(anyOutOfStock);

boolean noVeryCostlyProduct = items.stream().noneMatch(item -> item.getPrice() > 5000);
System.out.println(noVeryCostlyProduct);

Optional<Item> randomItemOptional = items.stream()
    .filter(item -> item.getPrice() > 1000)
    .findAny();
System.out.println(randomItemOptional);

Optional<Item> firstItemOptional = items.stream()
    .filter(item -> item.getPrice() > 1000)
    .findFirst();
System.out.println(firstItemOptional);
Slide 24

Chaining Stream Operations to Form a Pipeline

  • Build a readable chain where each step has one responsibility.
  • Typical flow: filter - transform - sort - collect.
  • Prefer short, composable lambdas over complex in-line business logic.
  • Pipeline clarity usually matters more than reducing line count.
Slide 25

Pipeline Step-by-Step Example

  • Step 1: keep odd values only.
  • Step 2: square each value to derive transformed metrics.
  • Step 3: sort final output and collect into a stable list.
List<Integer> input = List.of(5, 7, 2, 11, 4, 9, 13);

List<Integer> output = input.stream()
    .filter(num -> num % 2 != 0)
    .map(num -> num * num)
    .sorted()
    .collect(Collectors.toList());

System.out.println(output); // [25, 49, 81, 121, 169]
Slide 26

parallelStream()

  • Sequential streams use one thread; parallel streams split work across threads.
  • Use parallelStream() when each element has meaningful CPU work.
  • Avoid shared mutable state inside lambdas; it breaks correctness in parallel mode.
  • Order may differ unless you enforce ordered terminal behavior.
  • Benchmark before adopting parallel mode; not every workload gets faster.
departmentList.parallelStream().forEach(System.out::println);
Slide 26A

Parallel Stream Timing Demo

  • This example simulates expensive per-element work with Thread.sleep(100).
  • In parallel mode, different worker threads execute different items.
  • Console logs expose which thread handled each input value.
  • Elapsed time comparison demonstrates when parallel execution helps.
public class Test {
    public static int doubleIt(int n) {
        try {
            Thread.sleep(100);
            System.out.println(Thread.currentThread().getName() + " is sleeping n=" + n);
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }
        return n * 2;
    }

    public static void main(String[] args) {
        Instant now = Instant.now();

        int[] array = IntStream.range(0, 10)
                .parallel()
                .map(Test::doubleIt)
                .toArray();

        System.out.println(array.length);
        System.out.println("Time elapsed: " + (Instant.now().toEpochMilli() - now.toEpochMilli()) + " ms");
    }
}

Key takeaway: Parallelism is visible both in thread names and in lower total execution time for heavy work.

Slide 27

Mixing Sequential and Parallel Processing

  • Filter cheaply first, then parallelize expensive parts.
  • This minimizes parallel overhead and improves practical throughput.
  • Use this pattern for heavy transformations like encryption, scoring, or NLP parsing.
String names = persons.stream()
    .filter(Person::isMajor)
    .parallel()
    .map(Person::getName)
    .collect(Collectors.joining(", "));

Key takeaway: You can switch execution strategy mid-pipeline with parallel() when it truly adds value.

Slide 28

Collections vs Streams

Collections Streams
Data holder: stores elements in memory. Data processor: reads elements from a source on demand.
Eager structure; add/remove operations are direct. Lazy pipeline; transformations are defined first, executed later.
Usually iterated with external loops (for, while). Processed internally via operations (map, filter, reduce).
Reusable across multiple iterations. Consumable; one stream instance is typically used once.
General-purpose container API. Functional pipeline API with lambdas and collectors.

Key takeaway: Use collections to store and manage data, streams to express transformations and queries cleanly.

Slide 29

Practice Problem 1: Count Word Frequency in a Sentence

  • Goal: count how many times each word appears and print highest frequency first.
  • Operators used: map, filter, collect, groupingBy, counting, sorted, forEach.
  • This is a common text analytics pattern used in search, logs, and chat processing.
String sentence = "Java Stream stream API makes Java code cleaner and stream code readable";

Map<String, Long> freq = Arrays.stream(sentence.toLowerCase().split("\\W+"))
    .filter(word -> !word.isBlank())
    .collect(Collectors.groupingBy(
        Function.identity(),
        Collectors.counting()
    ));

freq.entrySet().stream()
    .sorted(Map.Entry.<String, Long>comparingByValue(Comparator.reverseOrder())
        .thenComparing(Map.Entry.comparingByKey()))
    .forEach(e -> System.out.println(e.getKey() + " = " + e.getValue()));

Key takeaway: This is the clean stream-based alternative to manual nested loops and mutable counters.

Slide 30

Practice Problem 2: Find the First Non-Repeating Character

  • Goal: from a sentence, find the first character that appears only once.
  • Operators used: mapToObj, filter, collect, groupingBy, findFirst.
  • Using LinkedHashMap preserves encounter order so “first” stays correct.
String sentence = "Swiss watches are awesome";

Optional<Character> firstUnique = sentence.chars()
    .mapToObj(c -> Character.toLowerCase((char) c))
    .filter(Character::isLetter)
    .collect(Collectors.groupingBy(
        Function.identity(),
        LinkedHashMap::new,
        Collectors.counting()
    ))
    .entrySet().stream()
    .filter(e -> e.getValue() == 1)
    .map(Map.Entry::getKey)
    .findFirst();

System.out.println(firstUnique.orElse('-'));

Key takeaway: Streams let you express “count + preserve order + first match” as one readable pipeline.

Slide 31

Practice Problem 3: Top 3 Customers by Paid Order Amount

  • Goal: aggregate paid orders per customer and print the top 3.
  • Operators used: filter, collect, groupingBy, summingDouble, sorted, limit, map.
  • This pattern is typical in ecommerce and reporting services.
record Order(String customer, double amount, String status) {}

List<Order> orders = List.of(
    new Order("Alice", 120, "PAID"),
    new Order("Bob", 80, "PAID"),
    new Order("Alice", 200, "PAID"),
    new Order("Eve", 50, "CANCELLED"),
    new Order("Bob", 170, "PAID"),
    new Order("Charlie", 300, "PAID")
);

orders.stream()
    .filter(o -> "PAID".equals(o.status()))
    .collect(Collectors.groupingBy(Order::customer, Collectors.summingDouble(Order::amount)))
    .entrySet().stream()
    .sorted(Map.Entry.<String, Double>comparingByValue(Comparator.reverseOrder()))
    .limit(3)
    .map(e -> e.getKey() + " -> $" + String.format("%.2f", e.getValue()))
    .forEach(System.out::println);

Key takeaway: The stream pipeline reads almost like business language: filter, group, rank, and print.

Slide 36

Cheat Sheet: Real-World Use Cases and Best Practices

Real-World Use Cases

  • E-commerce: filter active products, sort by price/rating, top N by category.
  • Banking: group by transaction type, detect suspicious patterns.
  • HR: filter by department, group by role, compute average salary.
  • Log analysis: count errors per day, extract unique users/IPs.
  • Inventory: low-stock filtering, supplier grouping, total stock value.

Best Practices

  • Prefer streams for meaningful data processing, not trivial loops.
  • Avoid mutating shared state inside pipelines.
  • Use method references when it improves readability.
  • Benchmark before using parallelStream().
  • Keep lambdas small, stateless, and intention-revealing.
List<String> names = List.of("Alice", "Bob", "Charlie", "David", "Bob");

List<String> result = names.stream()
    .filter(s -> s.length() > 3)
    .map(String::toLowerCase)
    .distinct()
    .sorted()
    .collect(Collectors.toList());

System.out.println(result); // [alice, charlie, david]
