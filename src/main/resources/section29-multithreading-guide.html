Program vs Process vs Thread

Foundations of modern concurrency: execution units, memory ownership, and scheduling behavior.

1. PROGRAM

A program is a passive set of instructions stored on disk (class/jar/executable files).

  • Not running
  • No CPU/RAM ownership
  • Static artifact
2. PROCESS

A process is a running instance of a program with its own address space and system resources.

  • Own memory space
  • Isolated from other processes
  • Contains one or more threads
3. THREAD

A thread is the smallest execution unit in a process. Threads share process memory and resources.

  • Lightweight execution path
  • Shared heap/resources
  • Multiple threads per process

Single Threading vs Multithreading

Single-threading is simpler; multithreading provides better responsiveness and throughput with added complexity.

Single Threading

  • Simpler code and easier debugging
  • Lower memory overhead
  • Good for linear and short workflows
  • Can block completely on I/O
Time -> one thread executes tasks in sequence
Task 1 Task 2 Task 3

Typical example: simple scripts or basic command-line tools.

Multithreading

  • Better responsiveness under mixed workloads
  • Concurrent progress across tasks
  • Shared-memory collaboration
  • Requires synchronization discipline
Time -> multiple threads advance work concurrently
A1 A2 A3
B1 B2 B3
C1 C2 C3

Typical example: web servers, IDEs, games, streaming services.

Concurrency vs Parallelism

Concurrency means many tasks make progress over time; parallelism means tasks truly execute at the same time on multiple cores.

Concurrency (Single Core Style)

  • One core switches between tasks rapidly
  • Tasks look simultaneous but are interleaved
  • Great for I/O-bound workloads
Single core timeline
T1 T2 T3 T1 T2 T3

Key mechanism: context switching by CPU scheduler.

Parallelism (Multi Core)

  • Tasks run at the same instant on different cores
  • True simultaneous execution
  • Strong fit for CPU-bound workloads

Examples: rendering, scientific compute, heavy data processing.

Slide 5

CPU Core, Context Switching, Scheduler

The OS scheduler and CPU cores determine when threads run and how efficiently system resources are used.

CPU Core

  • A core independently executes instructions
  • More cores enable more real parallel execution
  • Core count does not remove sync requirements
Example: 4 cores can run up to 4 CPU-bound threads in true parallelism.

Context Switching

  • CPU saves thread state and loads another
  • Enables concurrency on limited cores
  • Too many switches increase overhead
Important: excessive blocking and tiny tasks can hurt overall throughput.

Scheduler

  • Decides which runnable thread executes next
  • Balances fairness, latency, and throughput
  • Coordinates queues, priorities, and time slices
Goal: predictable response time with efficient CPU utilization.

Thread Lifecycle in Java

Java threads follow JVM-managed states. Understanding transitions is essential for debugging and safe design.

Thread lifecycle overview in Java

Java threads follow a well-defined lifecycle managed by the JVM.

Create and Start

Important Notes

  • A thread can be started only once
  • Use proper synchronization for shared data
  • Respect interruption and cancellation paths
