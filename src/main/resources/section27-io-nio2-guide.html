Lesson 19 - Java I/O and NIO.2

What Is I/O?

I/O means Input / Output. Reading data from a source or writing data to a destination.

Java has two main I/O families:

  • classic stream APIs (java.io)
  • NIO.2 file APIs (java.nio.file) for modern filesystem work

Both are used in real systems. NIO.2 is usually preferred for file path and file operation logic.

  • Input: file, network, console, memory
  • Output: file, API response, logs, stream sink
  • Lesson focus: correctness, performance, and safety

File

Represents a file or directory on the file system.

Core idea: java.io.File helps you describe and inspect file-system paths. It does not perform content I/O by itself.

Real life analogy

File is like an address on a map. It tells you where the file is, but not the content inside the file.

What can it do?

  • Represents a file or directory path
  • Provides information about the file
  • Helps create, delete, rename files/folders
  • Does NOT read or write data

Common Methods

exists() Checks if file exists
isFile() Checks if it is a file
isDirectory() Checks if it is a directory
length() Returns file size in bytes
getName() Returns file name
getAbsolutePath() Returns full path
createNewFile() Creates a new file
mkdir() / mkdirs() Creates a directory

Example

File file = new File("data.txt");
System.out.println(file.exists());
System.out.println(file.getName());
System.out.println(file.getAbsolutePath());
System.out.println(file.length());
File only represents the file. It does NOT read or write any data.

File Streams (Unbuffered)

FileInputStream and FileOutputStream are low-level byte streams for direct file read/write operations.

Main idea: These streams work directly with bytes and usually hit the disk on frequent calls. Good for binary data, but slower when heavily repeated without buffering.

FileInputStream

Reads bytes from file to program.

Data flows from the source file into your app one read at a time.

Key Features

  • Byte-based read stream
  • Unbuffered direct reads
  • Use for binary input
File inFile = new File("in.bin");
try (FileInputStream fis = new FileInputStream(inFile)) {
    byte[] chunk = new byte[1024];
    int read;
    long total = 0;
    while ((read = fis.read(chunk)) != -1) {
        total += read;
    }
    System.out.println("Read bytes: " + total);
} catch (IOException e) {
    e.printStackTrace();
}

FileOutputStream

Writes bytes from program to file.

↑

Data flows out of your app and gets written to destination file.

Key Features

  • Byte-based write stream
  • Unbuffered direct writes
  • Overwrite or append mode
byte[] dataBytes = "event=login".getBytes();
try (FileOutputStream fos =
         new FileOutputStream("out.bin", true)) {
    fos.write(dataBytes);
    fos.write('\n');
    fos.flush();
} catch (IOException e) {
    e.printStackTrace();
}
Note: Many small read() / write() calls can be slow. For performance, wrap with buffered streams on the next slide.
Where You Usually See It
  • Raw binary upload/download handlers
  • Low-level adapters under higher-level APIs
  • Short tools where simplicity is enough
Common Performance Mistakes
  • Reading one byte at a time in big files
  • Writing tiny chunks in tight loops
  • Skipping resource close on exceptions
Fast Upgrade Path
InputStream in =
    new BufferedInputStream(
        new FileInputStream("in.bin"));

Buffered Streams

BufferedInputStream and BufferedOutputStream improve I/O performance by reducing direct disk operations.

Main idea: Input stream reads large chunks into RAM, output stream accumulates writes in RAM and flushes to disk in batches.

BufferedInputStream

Reads bytes faster by buffering input.

Buy many eggs at once instead of one-by-one trips.

Key Features

  • Default buffer: ~8 KB
  • Fewer disk reads
  • Best for large files
try (BufferedInputStream bis =
         new BufferedInputStream(new FileInputStream(file))) {
    byte[] chunk = new byte[4096];
    int read;
    long total = 0;
    while ((read = bis.read(chunk)) != -1) {
        total += read;
    }
    System.out.println("Buffered read bytes: " + total);
} catch (IOException e) {
    e.printStackTrace();
}

BufferedOutputStream

Writes bytes faster by buffering output.

↑

Collect many bytes, then send in one batch to destination.

Key Features

  • Accumulates bytes in RAM
  • Fewer disk/network writes
  • Use flush() before critical boundaries
try (BufferedOutputStream bos =
         new BufferedOutputStream(new FileOutputStream(file, true))) {
    bos.write(dataBytes);
    bos.flush();
} catch (IOException e) {
    e.printStackTrace();
}
When to use: Use both together in backend pipelines: BufferedInputStream for fast reads and BufferedOutputStream for fast writes.
Best Fit Scenarios
  • Large media files and export jobs
  • Batch processing with many records
  • High-throughput import pipelines
Pitfalls to Avoid
  • Forgetting flush() before program end
  • Tiny custom buffers for huge files
  • Mixing text encoding logic with raw bytes
Production Pattern
try (InputStream in = new BufferedInputStream(...);
     OutputStream out = new BufferedOutputStream(...)) {
    in.transferTo(out);
}

FileInputStream vs BufferedInputStream

Data Flow Comparison

File on Disk
->
FileInputStream
reads directly from disk
->
Your Program
consumes data

BufferedInputStream variant: File on Disk -> BufferedInputStream (memory buffer) -> Program.

Why Buffering Is Important

Without Buffering (FileInputStream)
  • read() -> disk access
  • read() -> disk access
  • read() -> disk access
  • read() -> disk access

Many small disk accesses = SLOW

With Buffering (BufferedInputStream)
  • Disk access reads big chunk (e.g., 8 KB)
  • Data stored in RAM buffer
  • Program reads from memory quickly

Fewer disk accesses = FAST

Comparison Table

Feature File FileInputStream BufferedInputStream
Purpose Represents file/directory Reads bytes from file Reads bytes faster using buffer
Works With File and directory metadata Binary data (bytes) Any input stream (usually FileInputStream)
Data Type Path and info byte byte
Buffering No No Yes (default 8 KB)
Speed Not for reading Slow (many disk accesses) Fast (fewer disk accesses)
Uses Existence, create, delete, rename Read binary files Performance improvement for I/O
Example Use Case Check upload path and file info Read image/video/pdf directly Large files, uploads/downloads, streams

How To Use Together (Best Practice)

Always wrap FileInputStream with BufferedInputStream for better performance.

File file = new File("photo.jpg");
try (FileInputStream fis = new FileInputStream(file);
     BufferedInputStream bis = new BufferedInputStream(fis)) {
    byte[] buffer = new byte[1024];
    int bytesRead;
    while ((bytesRead = bis.read(buffer)) != -1) {
        // process buffer [0..bytesRead)
        System.out.println("Read bytes: " + bytesRead);
    }
} catch (IOException e) {
    e.printStackTrace();
}
Why byte[] buffer? We read many bytes at once into array memory. This reduces read() calls and improves speed.

Wrong vs Correct

WRONG (Avoid)
FileReader reader =
    new FileReader("data.txt");
  • Uses platform default charset
  • Can break across environments
CORRECT

    Path.of("data.txt"),
    StandardCharsets.UTF_8
);
  • Charset is explicit and stable
  • UTF-8 matches modern backend practice
Reader: Files.newBufferedReader(path, UTF_8)
Writer: Files.newBufferedWriter(path, UTF_8)
Encode: text.getBytes(StandardCharsets.UTF_8)
Decode: new String(bytes, StandardCharsets.UTF_8)

Important Rule + Real Bug

If text is saved with one encoding but read with another, characters corrupt (mojibake).

Always specify charset explicitly. Use UTF-8 end-to-end.

Character Streams and Practical Backend Mapping

Character streams are designed for text data and are encoding-aware; byte streams are for raw binary content.

Character Streams (Text Data)

Used for txt, json, xml, csv, config files, and application logs.

Main Classes
Reader Reads characters
Writer Writes characters
FileReader Reads text files
FileWriter Writes text files
Example: Read Text File
FileReader reader = new FileReader("data.txt");
int ch;
while ((ch = reader.read()) != -1) {
    System.out.print((char) ch);
}
reader.close();

Real Backend Use Cases

  • Upload imageByte stream
  • Read config fileCharacter stream
  • Generate PDFByte stream
  • Read CSVCharacter stream
  • Store logsCharacter stream

Safe File Handling in Backend Utilities

Prevent leaks, memory crashes, path traversal, and accidental overwrite when working with file uploads and storage.

1. Resource Leak

Bad
FileReader reader = new FileReader("data.txt");
reader.readLine(); // if exception: handle stays open
Best Solution
try (BufferedReader reader = Files.newBufferedReader(path)) {
  String line;
  while ((line = reader.readLine()) != null) { process(line); }
}

2. Large File Memory Crash

Bad
Files.readString(path); // huge file

Can cause OutOfMemoryError.

Better Solution
try (BufferedReader reader = Files.newBufferedReader(path)) {
  reader.lines().forEach(this::processLine);
}

3. Path Traversal Attack

Dangerous input: ../../etc/passwd

Bad
Path path = Path.of(userInput);

May access sensitive files.

Safer Approach
Path base = Path.of("uploads");
Path safe = base.resolve(userInput).normalize();
if (!safe.startsWith(base)) throw new SecurityException();

4. Overwriting Important Files

Always validate before writing:

  • Validate file name and extension
  • Validate file size and permissions
  • Use dedicated safe upload folder
  • Prefer UUID-based file names
Safe Write Pattern
Path target = uploadDir.resolve(uuidName).normalize();
Files.copy(in, target); // no direct user path write

Safe Upload Checklist

  • Avoid direct user-controlled paths
  • Normalize and validate every path
  • Use try-with-resources for I/O
  • Stream large files line-by-line
  • Use UTF-8 consistently in text I/O
Production rule: stream large files, validate and normalize paths, and always use try-with-resources.
